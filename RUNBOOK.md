# Ранбук: Планка 400к+

Локальный тренажёр: один процесс Go (`prep-server`) и Flutter Web, который этот процесс отдаёт сам. Отдельной базы, очереди и песочницы компиляции нет. Ревью кода и пояснение поиска ходят в OpenRouter, если задан ключ.

Оператор — тот, кто запускает процесс на своей машине. Внешнего дежурства нет.

## Состав

| Что | Где |
| --- | --- |
| Процесс | `prep_app/backend/prep-server`, по умолчанию `:8080` |
| Карточки и прогресс | SQLite `INTERVIEW_DB`, по умолчанию `/home/shaman/interview_questions.db` |
| Провалы | SQLite `HARD_CONCEPTS_DB`, по умолчанию `/home/shaman/hard_concepts.db` |
| Исходный дамп | `KNOWLEDGE_JSON`, иначе первый существующий файл из списка ниже |
| Статика | `WEB_DIR` или `prep_app/app/build/web` |
| Логи | stdout процесса. Файла логов нет |

Поиск дампа при старте, если `KNOWLEDGE_JSON` пуст:

1. `/home/shaman/prep_app_knowledge_export.json`
2. `prep_app/data/prep_app_knowledge_export.json` (от текущего каталога)
3. `data/prep_app_knowledge_export.json`
4. файл рядом с бинарником

Журнал SQLite — WAL, `busy_timeout` 5 секунд. Рядом с базой появляются `-wal` и `-shm`. Это рабочие файлы, не мусор.

## Перед стартом

Нужны Go (модуль `prepapp`, Go 1.22) и Flutter, если статики ещё нет. `run.sh` сам добавляет `/opt/flutter/bin` в `PATH`, когда бинарник лежит там.

```bash
export OPENROUTER_API_KEY=...                 # пусто — ревью и пояснение поиска выключены
export OPENROUTER_MODEL=openai/gpt-4o-mini    # пусто — модель openai/gpt-4o-mini
export ADDR=:8080
export INTERVIEW_DB=/home/shaman/interview_questions.db
export HARD_CONCEPTS_DB=/home/shaman/hard_concepts.db
export KNOWLEDGE_JSON=/absolute/path/prep_app_knowledge_export.json
```

Флаги перекрывают переменные: `-addr`, `-interview-db`, `-hard-db`, `-web`, `-auth-file`.

Каталог для файла базы создаётся сам, с правами `0700`, если его ещё не было. Файлы баз после открытия получают `0600`. Ключ в репозиторий и в командную историю не класть.

## Пароль

Пароль закрывает API. Статика сайта открыта, чтобы экран входа вообще загрузился. Карточки, прогресс, провалы и ключ OpenRouter лежат отдельно от пароля и этой настройкой не перезаписываются.

Хеш — Argon2id, профиль OWASP: 19 МиБ, 2 прохода, parallelism 1. В файле нет самого пароля, только хеш и хеши сессий. Файл по умолчанию — `prep_auth.json` рядом с `INTERVIEW_DB`. Другой путь: `PREP_AUTH_FILE` или `-auth-file`. Права файла `0600`.

Пока файла нет, с этой машины API открыт (чтобы задать пароль и не потерять доступ к уже набранному прогрессу), с телефона и из сети — нет. Первый заход на `http://127.0.0.1:8080` показывает форму. Минимальная длина — 12 символов. С телефона форму первого пароля сервер отвергает.

Дальше сессия живёт 7 дней. Браузер получает HttpOnly cookie `SameSite=Lax`. Приложение на телефоне держит bearer-токен в памяти процесса и спрашивает пароль заново после выгрузки. Запросы с cookie без заголовка `X-Prep-Client` не проходят. Пять неверных паролей с одного адреса замораживают вход на 15 минут.

Смена пароля в интерфейсе или через окружение закрывает все сессии. Базы и `OPENROUTER_API_KEY` не читаются этой операцией.

Если задавать пароль не из браузера:

```bash
export PREP_PASSWORD='длинная парольная фраза'
./prep_app/run.sh
# в логе будет строка, что хеш сохранён — после этого уберите PREP_PASSWORD из окружения
```

Замена уже сохранённого пароля без интерфейса, данные тренажёра не трогаются:

```bash
export PREP_PASSWORD='новая парольная фраза'
export PREP_PASSWORD_RESET=1
./prep_app/run.sh
```

Если `PREP_PASSWORD` не совпал с хешем и `PREP_PASSWORD_RESET` не задан, процесс не стартует и файл пароля не переписывает.

Чужой origin браузера к API не допускается. Для `flutter run` в Chrome на другом порту перечислите его в `PREP_ALLOWED_ORIGINS` (через запятую, без `*`). Нативное приложение на телефоне CORS не использует.

По Wi-Fi пароль и cookie идут открытым текстом, пока не заданы оба файла:

```bash
export PREP_TLS_CERT=/absolute/path/fullchain.pem
export PREP_TLS_KEY=/absolute/path/privkey.pem
```

Неполный набор или отсутствующий файл не запускает слушатель. Базы, хеш пароля и ключ OpenRouter при этом не меняются. Сертификат сервер сам не выпускает и старые ключи не ротирует. За `PREP_TRUST_PROXY=1` cookie становится Secure, если прокси прислал `X-Forwarded-Proto: https`. Тот же флаг берёт адрес клиента из `X-Real-IP`, иначе из первого адреса `X-Forwarded-For`. Без этого nginx с `127.0.0.1` выглядит как локальный вход, и первый пароль мог бы задать кто угодно снаружи. Включайте флаг только когда снаружи до процесса ходит сам прокси.

`GET /api/health` с этой машины по-прежнему отдаёт `items` и `ai`. С другого адреса без сессии остаётся только `{"ok":true}`, когда пароль уже задан.

После правок Dart удалите `prep_app/app/build/web`, иначе `run.sh` оставит старый экран без входа.

## Запуск и остановка

Из корня репозитория:

```bash
./prep_app/run.sh
```

Скрипт собирает `prep_app/backend/prep-server`, при отсутствии `prep_app/app/build/web/index.html` делает `flutter build web --release` и запускает сервер. Повторный запуск веб не пересобирает, пока `index.html` на месте.

Ожидаемые строки в stdout:

```text
база знаний: <путь> (<N> записей)
prep_items: <N>
listening on :8080
interview db: <абсолютный путь>
hard concepts db: <абсолютный путь>
```

Без ключа вместо молчаливого успеха будет строка `OPENROUTER_API_KEY не задан`. Пустая база — `prep_items пуст`. Каталог без `index.html` — `раздаю только API`, сайт при этом не открывается.

Остановка: `SIGINT` или `SIGTERM`. Процесс закрывает слушатель и даёт активным запросам до 5 секунд. `SIGKILL` обрывает ревью на середине; карточка при этом не помечается, если ответ клиенту не ушёл.

Второй экземпляр на том же `ADDR` не поднимется (`serve: bind`). Два процесса на одну и ту же пару файлов SQLite не запускать: WAL переживёт короткую блокировку, но прогресс начнёт писаться из двух мест.

Телефон в той же сети открывает `http://<ip-компьютера>:8080`. Отдельное приложение:

```bash
cd prep_app/app
flutter run --dart-define=API_BASE=http://<ip>:8080
```

Готовый APK или IPA, без кабеля к компьютеру разработчика, — в разделе [Сборка телефона и iOS](#сборка-телефона-и-ios).

Веб, который отдал сам сервер, берёт API с того же origin. Ширина меньше 768px — мобильный режим, шире — две панели для кода.

## Проверка

```bash
curl -sS http://127.0.0.1:8080/api/health
curl -sS http://127.0.0.1:8080/api/bar
```

`/api/health` с этой машины отвечает и после включения пароля. `/api/bar` без сессии отвечает, только пока пароль ещё не задан. Дальше нужен вход:

```bash
curl -sS -c /tmp/prep.jar -H 'Content-Type: application/json' -H 'X-Prep-Client: 1' \
  -d '{"password":"..."}' http://127.0.0.1:8080/api/auth/login
curl -sS -b /tmp/prep.jar -H 'X-Prep-Client: 1' http://127.0.0.1:8080/api/bar
```

Здоровый ответ health:

```json
{"ok":true,"items":123,"ai":true,"data_ready":true}
```

| Поле | Норма |
| --- | --- |
| `ok` | `true`, HTTP 200 |
| `items` | больше 0 после импорта дампа из репозитория |
| `data_ready` | `true`, когда `items > 0` |
| `ai` | `true` только если процесс стартовал с непустым `OPENROUTER_API_KEY` |

`GET /api/bar` отдаёт общий процент, дорожки и поле `today` / `today_track`. Календарь берётся с часов машины, где крутится сервер.

Каждый запрос пишется в stdout как `METHOD path status`.

## Утренний спринт

Одна карточка в день. Пропущенное пачкой не нагонять.

Дорожку выбирает сервер по локальной дате:

| День | `today_track` | Как отвечать |
| --- | --- | --- |
| Чётное число, не воскресенье | `dumps` | 5 минут вслух, потом скелет |
| Нечётное число, не воскресенье | `patterns` | 5 минут идея, 15 минут Go, стоп |
| Воскресенье | `system_design`, затем `legend` | 40 минут design или 15 минут один буллет легенды |

На главной кнопка `Утренний спринт` вызывает `GET /api/feed?mode=mobile&kind=sprint`. Если сегодняшняя дорожка уже закрыта, сервер берёт любую незакрытую карточку планки (`dumps`, `patterns`, `system_design`, `legend`). Порядок внутри дорожки: последний провал, затем ещё не отвеченные, затем реже спрошенные.

Текст «Протокол» на главной читается из таблицы `prep_protocol`. В дампе там ещё упомянуты `python3 ~/bigtech_prep.py today` и `done`. Этих команд в репозитории нет. Отметка дня — кнопка зачёта в тренажёре, не скрипт.

Зачёт:

- квиз — сервер сравнивает `selected_index` с `correct_index`, поле `passed` с клиента не решает;
- устный вопрос — зачтён, когда последний ответ верный (`last_result = 1`);
- код — зачтён только когда ревью вернуло `passed: true` (`closed = 1`).

Провал пишет строку в `hard_concepts` и поднимает `fail_count`. Следующий зачёт той же карточки ставит `resolved = 1`. Кнопка `Провалы` открывает незакрытые провалы, у которых есть `question_id`, сначала с большим `fail_count`.

С телефона кодовую задачу можно отложить: `POST /api/queue`. В очередь попадают только `item_type = code`. На широком экране она видна блоком «Очередь Web-задач». Успешное ревью удаляет задачу из очереди.

## Данные и прогресс

Импорт идёт при каждом старте, если дамп нашёлся. Это upsert по `id`. Текст карточки обновляется. Для уже существующей строки `prep_items` импорт не трогает:

- `times_asked`, `times_passed`, `last_result`, `closed`
- `status` (в `ON CONFLICT` это поле не перезаписывается)
- `options`, `correct_index`

Новая строка получает `status` из дампа (`new`, если в дампе пусто).

Идентификаторы:

- карточки планки — `id` из `prep_items` дампа;
- вопросы библиотеки — `10000 + id` вопроса, `track = library`;
- разобранные концепты — `20000 + id` концепта, `track = concept`.

Отдельно: повторный импорт перезаписывает `questions.is_answered`, `questions.user_notes` и `interview_tracker.user_understood` значениями из JSON. `interview_tracker.times_asked` берётся как максимум из базы и дампа. Прогресс планки на главной от этого не откатывается, но пометки «понял / ещё плавает» в блоке «Уже спрашивали» могут вернуться к состоянию дампа.

Импорт карточек и импорт таблицы `concepts` в базе провалов — две транзакции. Если вторая падает, карточки уже записаны. Следующий успешный старт дописывает концепты upsert-ом.

Эталон кода (`reference_code`) клиенту не отдаётся. В ревью он уходит только в промпт модели.

## Копия и восстановление

Остановить сервер. Скопировать оба файла базы вместе с их `-wal` и `-shm`, если они есть. Копия одного `.db` при живом WAL теряет последние записи.

```bash
# сервер остановлен
cp -a "$INTERVIEW_DB" "$INTERVIEW_DB.bak.$(date +%F)"
cp -a "$HARD_CONCEPTS_DB" "$HARD_CONCEPTS_DB.bak.$(date +%F)"
AUTH_FILE="${PREP_AUTH_FILE:-$(dirname "$INTERVIEW_DB")/prep_auth.json}"
cp -a "$AUTH_FILE" "$AUTH_FILE.bak.$(date +%F)"
```

`prep_auth.json` — это хеш пароля и сессии, не прогресс. Потеря файла не стирает базы и не трогает ключ OpenRouter: пароль задаётся заново. Копия файла без баз тоже не восстанавливает карточки.

`prep_settings.json` рядом с базой — выбранные в настройках модель и поставщик. Это не ключ и не прогресс. Потеря файла возвращает `OPENROUTER_MODEL`, базы и `OPENROUTER_API_KEY` не меняются.

Живую копию, не останавливая процесс, снимать через backup API sqlite, не через `cp`:

```bash
sqlite3 "$INTERVIEW_DB" ".backup '/tmp/interview_questions.db.bak'"
sqlite3 "$HARD_CONCEPTS_DB" ".backup '/tmp/hard_concepts.db.bak'"
```

Восстановление: остановить процесс, положить файлы на те же пути (или поменять `INTERVIEW_DB` / `HARD_CONCEPTS_DB`), поднять сервер, сверить `items` в `/api/health` и процент в `/api/bar`.

Сброс прогресса при сохранении текстов — осознанное действие, только на копии:

```sql
UPDATE prep_items
SET times_asked = 0, times_passed = 0, last_result = NULL, closed = 0, status = 'new';
DELETE FROM web_queue;
```

Провалы живут в другом файле: `DELETE FROM hard_concepts;` в `HARD_CONCEPTS_DB`. Таблицу `concepts` этим не трогать — это тексты разборов из дампа.

## Инциденты

### Процесс сразу завершается на `import …: json:`

Дамп найден, но JSON сломан. Слушатель не поднимается, старая база остаётся: транзакция карточек откатывается. Проверить, что `KNOWLEDGE_JSON` указывает на файл, а не на каталог и не на обрезанную выгрузку. Валидный дамп репозитория — `prep_app/data/prep_app_knowledge_export.json`.

### `prep_items пуст`, на главной ноль

Дамп не найден (смотрите каталог запуска: относительные пути считаются от cwd) или импорт ещё не был. Задать абсолютный `KNOWLEDGE_JSON` и перезапустить. В логе должна появиться строка `база знаний:`.

### Процесс сразу завершается на `auth:`

Файл пароля повреждён, `PREP_PASSWORD` не совпал с хешем или не задана пара TLS-файлов. Слушатель не поднимается. Сообщение прямо говорит, что базы и ключ не изменены. Повреждённый `prep_auth.json` не переписывается: его можно убрать в сторону и задать пароль заново, прогресс в sqlite от этого не откатывается. Несовпавший `PREP_PASSWORD` просто уберите из окружения и запустите снова со старым паролем.

### С телефона 401, на компьютере тренажёр открывается

Пароль ещё не задан. Откройте `http://127.0.0.1:8080` на машине с сервером и сохраните пароль. После этого телефон входит тем же паролем.

### Вход отвечает 429

С этого адреса было пять неверных паролей. Подождите время из заголовка `Retry-After` (до 15 минут). Базы в это время не блокируются.

### `serve: bind: address already in use`

Порт занят. Найти слушателя и остановить его, либо задать другой `ADDR`.

```bash
ss -ltnp | grep 8080
```

### Сайт не открывается, `/api/health` отвечает

Статики нет: в логе `раздаю только API`. Собрать веб и перезапустить.

```bash
(cd prep_app/app && flutter build web --release)
./prep_app/run.sh
```

`run.sh` пропускает сборку, если `index.html` уже есть. После правок Dart удалить `prep_app/app/build/web` или собрать Flutter вручную.

### Телефон не видит тренажёр

Сервер слушает все интерфейсы при `ADDR=:8080`. Проверить IP компьютера, что телефон в той же сети, и что запрос с телефона доходит: `curl` с другой машины на `http://<ip>:8080/api/health`. Для `flutter run` адрес задаётся один раз через `--dart-define=API_BASE=...`; смена IP требует нового запуска. Отдельное приложение без этого флага ходит на `http://127.0.0.1:8080`, то есть на сам телефон. Установленные APK и IPA используют адрес, который был в `API_BASE` во время сборки.

### Ревью отвечает 503 `OPENROUTER_API_KEY не задан`

Ключ не был в окружении в момент старта. `ai` в health будет `false`. Экспортировать ключ и перезапустить процесс. Поиск по базе при этом работает.

### Ревью отвечает 502

OpenRouter недоступен, ключ отвергнут, модель пустая или вернула не JSON. Текст ошибки — в теле ответа и в stdout. Таймаут клиента к OpenRouter — 60 секунд, таймаут записи HTTP — 90 секунд. Карточка не закрывается, пока клиент не получил `passed: true`. Повторить запрос. Модель по умолчанию — `OPENROUTER_MODEL`. Выбор в настройках сохраняется в `prep_settings.json` и действует без перезапуска; если поставщик закреплён и недоступен, ревью не уходит к другому. Сброс в настройках возвращает переменную окружения.

### Поиск без пояснения

`POST /api/search` всё равно отвечает 200. Пустое `explanation` значит, что ключа нет или вызов модели упал: в логе строка `search ai:`. Совпадения `matches` и `hard` от этого не зависят.

### `database is locked` или долгий старт

Второй процесс держит тот же файл, либо копирование идёт поверх открытой базы. Оставить один `prep-server`. Не удалять `-wal`/`-shm`, пока процесс жив.

### Прогресс обнулился после «просто перезапуска»

Штатный рестарт и повторный импорт прогресс планки не стирают. Так бывает, если процесс поднялся с другим `INTERVIEW_DB` (в логе другой абсолютный путь) или файлы базы заменили копией без WAL. Вернуть пару файлов из бэкапа и сверить путь в строке `interview db:`.

### Сегодняшняя кнопка открывает «чужую» дорожку

Сначала смотреть `today_track` в `/api/bar`. Воскресенье всегда design/легенда, чётность считается по числу месяца, не по дню недели. Если дорожка дня закрыта, спринт честно уходит на другую незакрытую карточку планки.

### В очередь не встаёт задача

`POST /api/queue` принимает только кодовую карточку. Для устного вопроса ответ — `в очередь Web попадают только кодовые задачи`.

## Сборка телефона и iOS

Workflow `.github/workflows/mobile.yml`, в Actions он называется «Сборка телефона». Flutter в нём закреплён на `3.47.7` — это ревизия из `prep_app/app/.metadata`.

Релиз — это git-тег. Push в `main` и pull request только проверяют, что проект собирается, и кладут файлы в артефакты Actions на 30 дней. Страница Releases пополняется, когда в репозиторий приходит тег.

### Релиз по тегу

Тег вида `v1.2.3` или `v1.2.3+4`. Он должен указывать на коммит, в котором уже есть workflow `.github/workflows/mobile.yml`. До слияния этой сборки в `main` тег релиз не создаст.

```bash
git checkout main
git pull
git tag v1.0.0
git push origin v1.0.0
```

Дальше Actions собирает APK и IPA и публикует GitHub Release с тем же именем. Имя версии в приложении берётся из тега. Номер сборки — из `+4`, а если его нет, из номера запуска Actions. Повторный запуск того же тега перезаписывает файлы релиза.

На теге в сборку попадают секреты подписи, если они заданы. В pull request секреты не попадают.

### Проверочные сборки

Запускаются сами:

- push в `main`, если менялись `prep_app/app`, скрипты сборки или сам workflow;
- pull request с теми же путями;
- вручную: Actions → Сборка телефона → Run workflow.

Три job: тесты, Android APK на Linux, iOS IPA на runner `xcode-27`. Без тега четвёртая job «GitHub Release» пропускается. Артефакты лежат 30 дней: `prep-app-android-<номер>` и `prep-app-ios-<номер>`. Вне тега имя версии берётся из `pubspec.yaml`, номер сборки — `github.run_number`.

Адрес сервера компилируется в приложение (`--dart-define=API_BASE`). Откуда он берётся, по порядку:

1. поле `api_base` у ручного запуска;
2. переменная репозитория `API_BASE` (Settings → Secrets and variables → Actions → Variables);
3. иначе `http://127.0.0.1:8080`.

На телефоне `127.0.0.1` — это сам телефон, тренажёр так не откроется. Для домашней сети задайте `API_BASE=http://<ip-компьютера>:8080`. Этот адрес попадает в APK, IPA и в лог сборки. Репозиторий публичный, артефакт может скачать любой пользователь GitHub, так что в `API_BASE` не кладут секреты. Смена IP — новый запуск workflow, не перезапуск сервера.

Release-сборка ходит по обычному HTTP: у сервера нет TLS. В Android включён cleartext, в iOS — `NSAllowsArbitraryLoads`.

Локально из корня репозитория, нужен Flutter 3.47.7:

```bash
API_BASE=http://192.168.1.10:8080 ./prep_app/scripts/build_mobile.sh android
API_BASE=http://192.168.1.10:8080 ./prep_app/scripts/build_mobile.sh ios    # только macOS
API_BASE=http://192.168.1.10:8080 ./prep_app/scripts/build_mobile.sh all
```

Файлы появляются в `prep_app/app/build/mobile-out/`. Рядом текстовый `*-build-info.txt`: адрес, версия, была ли своя подпись.

### Android

Без секретов APK подписывается debug-ключом раннера. Его можно поставить на устройство. Ключ раннера не постоянный: если Android откажется обновлять уже установленное приложение, его удаляют и ставят заново.

Свой keystore даёт одну и ту же подпись каждой сборке. Файлы ключей в репозиторий не класть. Секреты Actions, не variables:

| Секрет | Что это |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 release.jks` на Linux, на macOS `base64 -i release.jks \| tr -d '\n'` |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища |
| `ANDROID_KEY_ALIAS` | alias ключа |
| `ANDROID_KEY_PASSWORD` | пароль ключа; если его нет, берётся пароль хранилища |

Создать хранилище локально и не коммитить его:

```bash
keytool -genkeypair -v \
  -keystore release.jks -alias prep_app \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=Prep App, O=Personal, C=RU"
```

В pull request секреты в сборку не попадают. Подписанный APK дают тег, push в `main` и ручной запуск.

`applicationId` сейчас `com.example.prep_app`. Для установки с файла этого хватает. В Play такой идентификатор не примут.

### iOS

Без сертификата job собирает IPA без подписи (`*-unsigned.ipa`). На iPhone он не ставится: Apple не ставит неподписанное приложение. Файл нужен, чтобы убедиться, что проект собирается, и чтобы подписать его у себя.

Чтобы Actions отдавал IPA, который ставится на устройства из профиля, нужны секреты:

| Секрет | Что это |
| --- | --- |
| `IOS_CERTIFICATE_BASE64` | сертификат `.p12` (Apple Development или Apple Distribution) в base64, одной строкой |
| `IOS_CERTIFICATE_PASSWORD` | пароль `.p12` |
| `IOS_PROVISIONING_PROFILE_BASE64` | `.mobileprovision` в base64, одной строкой |

Переменные, не секреты:

| Переменная | Что это |
| --- | --- |
| `IOS_BUNDLE_ID` | обязательна, если в профиле маска `*`. Иначе берётся из профиля и должна с ним совпасть |
| поле `ios_export_method` ручного запуска | `auto`, `development`, `ad-hoc`, `app-store`, `enterprise`. `auto` смотрит на профиль |

В проекте bundle id `com.example.prepApp`. Настоящий профиль Apple на `com.example.*` не выпускает, поэтому для подписи задают свой id: он попадёт в сборку, в git `project.pbxproj` не переписывается.

`development` и `ad-hoc` ставятся только на устройства, чьи UDID есть в профиле. `app-store` — это IPA для TestFlight или App Store, не для прямой установки. Workflow в App Store Connect ничего не загружает.

В pull request iOS тоже без подписи, даже если секреты заданы.

## Чего не делать

- Не коммитить `*.db`, `*.db-wal`, `*.db-shm`, `prep_auth.json` и ключ OpenRouter.
- Не удалять `prep_auth.json`, чтобы «сбросить доступ», не отложив копию: базы останутся, но пароль придётся задать заново. И наоборот, не затирать базы ради нового пароля.
- Не коммитить keystore, `.p12`, `.mobileprovision` и `ios/Flutter/Signing.xcconfig`. Подпись живёт в секретах Actions.
- Не править прогресс в SQLite, пока сервер запущен.
- Не удалять `-wal`, чтобы «почистить место», при живом процессе.
- Не затирать `interview_questions.db` свежим пустым файлом ради нового импорта: тексты и так обновятся, а прогресс пропадёт.
- Не ждать локальной сборки и прогона Go: ревью только модельное.
